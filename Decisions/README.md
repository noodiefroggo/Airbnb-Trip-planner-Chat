# Decision Log — Airbnb Trip-Planner Chat

This folder is the single place where the project's decisions are recorded. Each task gets its own file. The files record what we chose, what else was on the table, and why. Use them to rebuild the story for a portfolio case study, or to see why something is the way it is before changing it.

## Project context (one line)

Guests quit before they see a single listing, because filters make them build a trip alone. The bet is a chat that plans a whole weekend (stay, experience, food) in one place. Leaders judge it by using a live prototype, and 8 UX-research guests test it. Source: [Meeting-Notes.md](../Meeting-Notes.md).

## How to add a task

Copy this skeleton into `Task-NN-Short-Name.md` and add a row to the index above.

```markdown
# Task NN — <name>

**Date:** YYYY-MM-DD · **Inputs:** <files, briefs, feedback> · **Outputs:** <files, links>

## Goal
<one or two sentences: what the task had to produce and for whom>

## Decisions
### D1. <decision in a few words>
- **Chose:** …
- **Alternatives:** …
- **Why:** …
- **Impact / trade-off:** …

## Feedback received and how it changed things
- <feedback> → <change>

## Open questions / follow-ups
- …

## Portfolio notes
<the 2–3 points worth telling in a case study>
```

Write decisions down as they're made, not reconstructed at the end. Record a decision that was reversed as well, with the reason.
