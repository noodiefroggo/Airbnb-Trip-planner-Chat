Trip-planner chat · Prototype spec

Card and error-state spec

One chat request, three cards, and the chat is never blank. This spec turns the hand sketches in sKETCHES/ into card layouts, field lists, a blank mock response and the error states. The build plan is in Meeting-Notes.md.

The happy path

Guest asks"Plan me a weekend in Kyoto". No login needed.
→
Typing bubbleThree dots while the plan loads.
→
Three cardsStay, Experience, Food, always in this order.
→
Act on a cardAdd to trip, pick a time, browse the menu.

When it goes wrong

Request failsError bubble with a red warning sign.
→
Try againSends the same request again.
→
Three cardsThe chat recovers.
Can't be plannedFor example, two countries in 2 days.
→
Go with suggestionSends a request the chat can plan.
→
Three cardsFor the suggested trip.

Three cards that never look alike

Build rules

One component per cardStayCard, ExperienceCard and FoodCard are separate, so the layouts stay truly different.
StackTypeScript, Next.js, React and Tailwind. Code on GitHub, one public Vercel link.
ReachNo login. Works on mobile and web.
Never blankEvery error has a button that brings the three cards back.

PartValue
Error copyShort, plain, no blame. Says what happened.
Try againInside the error bubble, bottom right. Sends the same request again.
SuggestionShown only when the request can't be planned as asked (for example, two countries in 2 days).
Forced failureAdd ?fail=once to the address. The first request fails and every request after it works.
Rule: both buttons end with the Stay, Experience and Food cards showing, in that order.
Original sketch: full error mockup
Steps to fire the forced failure
1. Open the live link with ?fail=once on the end.
2. Type "Plan me a weekend in Kyoto" and press Send.
3. The typing bubble shows, then the error bubble appears.
4. Tap Try again. The three cards appear in order.
